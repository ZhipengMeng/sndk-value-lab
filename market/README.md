# Automatic market prices

Only the quote is refreshed. Company operating scenarios, earnings estimates, cash-flow forecasts, share counts, ADS ratio, FX assumptions and October 9, 2026 valuation date remain separate and unchanged. A newer quote is compared with the dated model valuation; this does not roll the valuation date forward or update fundamentals.

All four pages read one public batch from [`mu-value-lab/main/market/quotes.json`](https://raw.githubusercontent.com/ZhipengMeng/mu-value-lab/main/market/quotes.json). Each page embeds its own identical client, so the company models stay standalone. `quotes.js` is copied into the three repositories; update and test all copies together.

The feed uses Yahoo Finance chart metadata for SNDK, MU and SKHY regular-session USD prices. SKHY is the Nasdaq ADS, not the Korean ordinary-share price. Source identity, exchange, currency, instrument, numeric prices and timestamps are validated; the original source link and quote time remain visible. Split events after the financial snapshot stop publication until share assumptions can be reviewed. There is no automatic KRW/USD conversion or after-hours-price substitution.

The central repository's `Refresh market prices` workflow fetches a complete batch at minutes 7, 22, 37 and 52 during 13:00–22:59 UTC on weekdays, covering U.S. standard/daylight regular sessions plus a buffer. It can also be run manually. The job replaces only `market/quotes.json` after all three quotes validate, then commits that data file. It has repository contents-write permission; no paid API key or personal account data is needed. Bot pushes do not trigger the normal site workflow. Model releases do not need to be redeployed for each quote change.

Web pages fetch on load, check every five minutes while visible, refresh after returning to the tab, and offer **Refresh prices**. GitHub's cache, queue and the provider can add delay; this is not streaming or execution-quality pricing. A failed or invalid batch retains the last valid batch. Local browser storage caches public quotes only. If no valid quote is available, the embedded October 9 close is shown with a fallback label. A feed older than 90 minutes or quote older than four days is visibly flagged. Weekends, holidays and trading halts can produce old quote timestamps even after a successful check.

Turn off **Update automatically** to reproduce the October 9 price comparisons. Downloaded local HTML starts in snapshot mode and makes no requests unless the user enables automatic prices. Assumption exports retain their original company model and record quote context separately. Importing an assumptions file never replaces reported facts with live prices.

The top comparison uses current controls and selected quotes. Its earnings, cash-yield, price-risk, grid and break-even checks below retain their labeled original operating scenarios and reprice against the same quote batch. Historical SNDK audit values remain dated historical results.

Validation includes malformed/foreign-currency/future/extended-hours/split rejection, unchanged files on provider failure, price-only changes to P/E/upside/rankings, preservation of cash flows and customized assumptions, failed-fetch and snapshot fallback, and desktop/mobile layout. `browser_report.json` records hashes of the tested HTML. The mutable feed is intentionally outside the immutable source-release checksum manifest and ZIP.

References: [Yahoo exchange/data timing](https://help.yahoo.com/kb/finance/article-exchanges-data-delays-sln2310.html), [GitHub scheduled workflow limitations](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). GitHub can delay or drop scheduled jobs and disables schedules after 60 days of repository inactivity; successful feed commits normally keep this repository active. The public provider interface has no availability guarantee. An updater failure is visible in Actions and on the page through dated/stale feed status.
